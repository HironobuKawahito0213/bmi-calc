# manual-video — 制作物の操作マニュアル動画を自動生成する

Playwright でブラウザを実際に操作しながら録画し、ffmpeg で配布用の動画にする。
Claude の仕事は **「何をどの順で見せ、どう説明するか」のシナリオを書くこと**。
録画・スクショ・字幕・mp4 化はすべて同梱スクリプトがやる。

## 出力物

`<outdir>/` に以下が揃う。納品や README 貼り付けにそのまま使える。

| ファイル | 内容 |
|---|---|
| `manual.mp4` | 字幕・ハイライト・カーソル付きの操作動画 (H.264, 1280x720) |
| `manual.gif` | `--gif` 指定時。README / Slack 用 |
| `manual.md` | 各ステップのスクショ＋説明文の手順書 |
| `screenshots/NN-*.png` | ステップごとの「操作前（ハイライト付き）」と「操作後 (`-after`)」 |
| `scenario.json` / `timeline.json` | 再生成・調整用 |

## 手順

### 1. 制作物を把握する

ソース (HTML / テンプレート / ルーティング / コンポーネント) を読んで、次を洗い出す。

- 画面の一覧と遷移（どのボタンでどこへ行くか）
- 入力項目とその制約（必須、単位、形式）
- 「できること」の単位（計算する、送信する、検索する、保存する…）
- 要素を特定できるセレクタ（`id` が最良。なければ `text=ボタン名`、`[name=...]`、`role` 系）

**動く状態の URL が必要**。静的 HTML なら `file:///絶対パス/index.html` でよい。
サーバーが要るものは先に起動する（例: `npx http-server -p 8080 &`、`npm run dev &`）。
起動したら `curl -s URL | head` などで本当に応答することを確かめてからシナリオに進む。

### 2. シナリオ JSON を書く

`assets/example-scenario.json` をコピーして書き換えるのが早い。フィールドの詳細は
`references/scenario-schema.md` を読む。

書き方の指針（これがマニュアルの品質をほぼ決める）:

- **最初の 1 ステップは画面全体の紹介**（action なし、`highlight` にタイトルや主要領域）。読む人は「今どこにいるか」から知りたい。
- **1 ステップ = 1 操作**。「入力して押す」は 2 ステップに分ける。動画で追えるし、スクショも 1 枚ずつ残る。
- **字幕は「操作 → 結果」の形**で書く。「『計算する』を押すと、BMI が計算されます」「『次へ』を押すと確認画面に移ります」。視聴者は次に何が起きるか知ってから見たい。
- **最後は結果を見せるステップ**で終える（action なし、`highlight` に結果の要素）。操作したまま終わると「で、どうなったの?」が残る。
- 字幕は 1 文〜2 文、40 字程度まで。長い補足は `note` に書くと Markdown 側にだけ出る。
- 入力値は現実的なサンプルにする（身長 170、メール `taro@example.com` など）。ダミーの `aaa` は説明として伝わらない。
- 画面遷移するステップには `waitFor` に遷移先の要素を入れると、ロード待ちで失敗しない。
- 画面が小さく要素が読みづらい制作物は `"zoom": 1.5` のように拡大する。

### 3. 生成する

```bash
SKILL=<このスキルのディレクトリ>
bash $SKILL/scripts/make_video.sh scenario.json ./manual-video --gif
```

オプション:

- `--narration` … 字幕文を日本語音声 (edge-tts, 要ネット接続) にして動画に重ねる。失敗したら自動で字幕のみにフォールバックする。
- `--headed` … デバッグ用にブラウザを表示する。

各ステップの表示時間は字幕の文字数（とナレーションの長さ）から自動で決まる。手動で延ばしたいときは `wait` (ms) を指定する。

### 4. 必ず自分の目で確認する

生成後に `screenshots/` の PNG を Read で何枚か見て、次を確認する。

- ハイライトが意図した要素に付いているか（セレクタ違いで別要素が光っていないか）
- 字幕が画面の重要な部分を隠していないか（隠すなら `viewport.height` を増やすか、字幕を短くする）
- 入力値や結果が実際に反映されているか（`-after.png` で確認）
- `timeline.json` に `error` が付いたステップがないか（exit code 2 で知らせる）

おかしければシナリオを直して再生成する。1 回で完璧を狙うより、2〜3 回回す方が早い。

### 5. 納品時に伝えること

ユーザーには出力場所と、動画の長さ・ステップ数、確認して気づいた点（例: 「送信後のメッセージが一瞬で消えるので `wait` を長めにしました」）を伝える。
動画や PNG は Read では映像として再生できないので、ユーザーが自分で再生して確認する前提で、見どころを文章で添える。

## よくある詰まりどころ

- **要素が見つからない**: Playwright のセレクタは `#id`、`text=計算する`、`button:has-text("送信")`、`[name=email]`、`role=button[name="保存"]` などが使える。開発者ツールで確認した `id` が最も壊れにくい。
- **SPA でクリック後に真っ白な画面が撮れる**: `waitFor` に遷移先の要素を指定する。
- **alert / confirm が出る**: 自動で OK を押して `manual.md` の「表示されるダイアログ」に記録する。`promptAnswer` で prompt の入力値を指定できる。
- **ログインが必要**: ログイン操作自体をステップにする（パスワードは `fill` で入力されるので、動画に映る点に注意。ダミーアカウントを使う）。
- **playwright がない**: `npm i -g playwright && npx playwright install chromium`。`ffmpeg` も必要。
- **長すぎる動画**: ステップを絞る。マニュアル動画は 1 本 1〜2 分、10 ステップ前後が見てもらえる上限。機能が多いなら機能ごとにシナリオを分けて複数本にする。

## 同梱スクリプト

- `scripts/make_video.sh` — 一括実行（narrate → record → compose）
- `scripts/record.js` — Playwright で操作・録画・スクショ・manual.md 生成
- `scripts/narrate.py` — 字幕文から音声生成（任意）
- `scripts/compose.py` — webm → mp4 / gif 変換、音声合成
- `assets/example-scenario.json` — BMI 計算機のシナリオ例
- `references/scenario-schema.md` — シナリオ JSON の全フィールド
